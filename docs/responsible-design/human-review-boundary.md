# Responsible design and human-review boundary

An unusual-activity score is evidence for review, never proof of fraud. User-facing language uses “unusual,” “operational signal,” and “requires review.” The safety validator rejects generated accusations and automatic account restrictions.

Deterministic rules define permitted action categories. OpenAI output is validated, cited, and treated as advisory evidence. Missing credentials, invalid output, timeouts, and safety failures return deterministic human-review guidance.

Every consequential case mutation requires a database-backed synthetic identity, scope authorization, current status, and expected version. Resolution requires a recorded human decision and verified note. Denials and accepted actions are audited without copying note bodies, customer data, prompts, advisory prose, or credentials into audit metadata.

The prototype contains no demographic or protected-attribute features. Context adjustments such as Eid discounts are explicit and visible. Real-world use would require production authentication, provider governance, representative validation, calibrated thresholds, appeal processes, and ongoing fairness monitoring.
